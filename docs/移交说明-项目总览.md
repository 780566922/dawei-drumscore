---

## 1. 项目是什么

一个给 **MuseScore 4** 用的 **VST3 音频播放插件**。

**解决什么问题**：MuseScore 自带的音频播放方案（如 vstPlayer）要求用户**先把音频裁好**再导入，还有演示版周期性静音的坑。本插件让用户**直接拖入完整音频**，然后在波形上拖一条「起始偏移」，把音频与谱面的第 1 小节对齐即可 —— 网格线会画在波形上，对齐没对齐一眼能看出来。播放头随谱面位置同步移动。

**作者身份**：B 站「大伟鼓谱」（品牌在界面底部页脚，鼓谱 / 教学 / 伴奏）。

**当前状态**：**三平台（macOS / Windows / Linux）均已构建发布**，但**只有 macOS 经过实机验证**。

### 架构要点

三平台共用同一个纯虚接口 **`ap::PlugView::Backend`**（定义在 `source/gui.h:47-108`）。

- **GUI 层只负责画**，所有数据（音频、峰值、偏移、宿主时间轴）都从 Backend 取。
- **数据与逻辑全在共用文件里**：`player.cpp`（播放）+ `aplaysdk.cpp`（VST3 胶水 + 真实状态）。
- `aplaysdk.cpp:74` 的 `StableBackend` 是个**无状态永生转发器**，函数内 static、地址在进程生命周期内恒定 —— 编辑器视图拿着的指针永不失效。所有调用前先 `currentProcessor()` 取一次真实处理器。
- 因此**跨平台问题优先怀疑平台 GUI 文件，逻辑问题才看共用文件**。

## 4. 构建

### macOS（唯一经过实机验证的平台）

```bash
./build.sh          # 编译 + 6 道自动验证（全绿才算成功）
./make_pkg.sh       # 打成 dist/大伟鼓谱MuseScore音频播放器-1.0.0.pkg
```

`build.sh` 的 6 道验证（缺一不可）：
1. 二进制架构（必须 universal：x86_64 + arm64，**MuseScore 会跳过非 universal 的插件**）与导出符号
2. `Info.plist`
3. bundle 结构
4. `validate` —— 插件结构与接口断言
5. `e2e_test` —— 真跑音频文件验证播放
6. `race_test` + 逐格式解码探测（AVFoundation 个别分支会抛 ObjC 异常，没人接就是宿主闪退）

SDK 路径走环境变量 `VST3_SDK_DIR`（默认 `~/WorkBuddy/vst3sdk`，SDK 版本 3.8.1），**脚本里不硬编码本机路径**。

## 5. 铁律（违反会出问题，都是踩过的）

### 5.1 MuseScore 插件菜单的命名规则

MuseScore 的 VST 菜单是 `VST → 厂商名 → 插件名`：

- **第二级「插件名」显示的就是 bundle 文件名**（去掉 `.vst3`）。证据：MuseScore 缓存 `known_audio_plugins.json` 的 `id` 字段 == bundle 文件名，**与 VST3 类名 `ci.name` 无关**。
  → 想让菜单显示中文，就**把 bundle 文件名设成中文**。
- **第一级「厂商名」走较弱编码通道，中文会乱码** → 厂商名**必须纯 ASCII**。
- **bundle 内可执行文件名保持 ASCII**（避免路径层编码问题），它不参与菜单显示。
- `ci.name` 仍应保持正确（其他宿主可能用它），`getClassInfoUnicode` 要重写做真正的 UTF-8→UTF-16 解码（SDK 基类 `fromAscii` 只逐字节拓宽）。

当前命名：bundle = `大伟鼓谱MuseScore音频播放器.vst3`；厂商 = `Dawei DrumScore`；可执行 = `DaweiDrumScore`。

> 换 bundle 文件名后，MuseScore 会当新插件重新扫描；旧的缓存条目要手动清理。

### 5.2 改 UI 布局必须同步更新验证器

改任何布局后，`validate.cpp` 里的尺寸/类名断言、`gui_repro.mm` 的控件计数都要同步，否则构建直接失败。
面板尺寸改动要**同步 4 处**：`initWithFrame` / `PlugView::m_view.frame` / `getSize` / `checkSizeConstraint`（Windows 版对应 `kPanelW/kPanelH`、`layoutChildren`、`getSize`、`checkSizeConstraint`）。

### 5.3 播放状态必须跟随宿主

插件音频的 `playing` 必须跟随宿主的 `kPlaying` 位（`ProcessContext.state & 0x0002`），否则宿主暂停时音频继续走，出现**两个播放头「分家」**。

### 5.4 CMake 开关名必须验证真的生效

CMake 对「set 一个 SDK 里不存在的变量」**不报错、不警告，只静默失效**。
曾把 VSTGUI 开关写成 `SMTG_ADD_VSTGUI`（真名是 `SMTG_ENABLE_VSTGUI_SUPPORT`，且默认 **ON**），结果 `vstgui4` 照样被引入，在 Linux 上强制探测 xcb-util/wayland/cairo/pango 一大串 → CI 卡在配置阶段，而报错信息里完全看不出根因。
**改完开关一定要用 `cmake --build <dir> --target help` 确认目标列表里没多出不想要的目标。**

### 5.5 三平台模块入口符号（各不相同，别搞混）

| 平台 | 必需导出 |
|---|---|
| macOS | `bundleEntry` / `bundleExit` / `GetPluginFactory` |
| Windows | **只需 `GetPluginFactory`**（`InitDll`/`ExitDll` 在 SDK 里标为 optional） |
| Linux | `ModuleEntry` / `ModuleExit` / `GetPluginFactory` |

**底层事实**：SDK 的 `smtg_target_add_library_main()` 只在 `public_sdk_SOURCE_DIR` 可见时才加 `*main.cpp`，而那个变量定义在 SDK 自己的 directory scope、传不回父作用域 —— **三个平台的入口其实一直是我们在 `aplaysdk.cpp` 里自己提供的**。
⚠️ **不要去设 `public_sdk_SOURCE_DIR`**（会把 SDK 的 main 文件也拉进来，和我们自己的入口符号撞车）。

### 5.6 发布资产名必须 ASCII

`gh release` 上传**会吞掉资产名里的中文**（`大伟鼓谱…pkg` → `MuseScore.-1.0.0.pkg`）。品牌中文放 Release 标题/说明里。
以 `-` 开头的资产名 `gh release delete-asset` 删不掉（被当 flag 解析），要改走 `gh api -X DELETE repos/$R/releases/assets/$ID`。

## 6. 宿主（MuseScore）交互的已知边界

- MuseScore **不提供** tempo / 拍号（实测 `tempoN=0x0000`），只给 `projectTimeSamples`（谱面位置）和 `kPlaying` 位。
  → 代码里 `HostTimeline` 有 `tempoValid` / `timeSigValid` 字段，但 MuseScore 不会填；网格速度实际靠**用户手填 BPM** 或回退默认 120。
- **VST3 协议无法让插件反向控制宿主的播放/暂停/seek**。「回到播放头」这类按钮只能做自身操作
  （重新对齐音频 + 把视野挪过去），动不了宿主的播放位置。
- MuseScore 的 VST 编辑器是**独立浮动窗口**，会抢 key window，导致空格键到不了宿主。
- 拍号语义：每拍时长 = `(60/BPM) × (4/分母)`。

## 8. 开发/推送环境

### macOS 开发机

- SDK：`~/WorkBuddy/vst3sdk`（3.8.1）
- **`CACurrentMediaTime` 属 QuartzCore，AppKit 工程默认不链接**，计时用 `systemUptime`
- **macOS 没有 `timeout` 命令**（`timeout 60 gh ...` 会 `command not found`，容易被误判成「命令无输出」）
- BSD `grep` 不支持 BRE 的 `\|`，多分支要写 `grep -E "a|b"`，否则**静默 0 匹配**
- BSD `sort` 不支持 `-V`（CI 上的 GNU sort 支持），本地别用它比版本号
- zsh 里 `$VAR` 不按空格分词，要用 `${=VAR}`

### 推 GitHub

必须走本机代理（梯子需开启）：

```bash
export PATH="$HOME/.local/bin:$PATH"
export HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897
# 沙箱里 git 不认环境变量代理，要显式指定：
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main
```

- 推送含 `.github/workflows/` 的提交要求 token 带 **`workflow` scope**（`gh auth refresh -s workflow`，且**必须用受管后台任务跑**，`nohup &` 起的进程会被回收，导致授权白做）
- `gh api --input -` 走管道会报 JSON 解析错 → 用 `--input /tmp/body.json`
- 改完 `.github/workflows/*.yml` **必须用 PyYAML 校验**（首行曾缺 `#`，整个工作流非法）

## 10. Windows 版特别提示（接手前必看）

1. **Windows 版从未在真机跑过**，所以「编译过 + CI 过」不等于「能用」。这次波形问题就是典型：编译、打包、CI、结构校验全过，一上机就露。
2. **CI 不渲染 GUI**，所以 GUI 类问题 CI 永远抓不到，必须人工看。
3. 排查 Windows GUI 问题时，记得**面板上的控件是两种东西**：
   - 真正的 Win32 控件（按钮 / 标签 / 下拉框 / 滑块）→ 系统自己画，基本不会出问题
   - **波形区是自绘的**（`source/win/gui_win.cpp` 的 `WinView::paint()`，走 `CreateCompatibleDC` + `BitBlt`）→ 出问题基本都在这里
4. 日志：崩溃日志在 `%USERPROFILE%\DaweiDrumScore.log`。
