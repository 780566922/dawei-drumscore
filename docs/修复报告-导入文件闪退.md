## 一、先取证，不猜

上一轮为这一刻专门装的崩溃取证首次立功。`~/Library/Logs/APLAY.log` 里躺着两条完整现场：

```
[20:18:43] 载入请求: .../美人鱼-林俊杰.mp3
[20:18:43] 解码完成: 12005053 帧, 采样率 48000
[20:18:43] 载入成功: 时长 250.11 秒
=== APLAY 崩溃: SIGSEGV (signal 11) ===
2   APLAY   -[GUIView loadPath:] + 368
3   AppKit  -[NSApplication(NSResponder) sendAction:to:from:] + 560

[20:19:00] 编辑器视图已挂载
=== APLAY 崩溃: SIGSEGV (signal 11) ===
2   APLAY   -[GUIView hasAudioURL:] + 232
3   APLAY   -[GUIView draggingEntered:] + 12
```

两条关键信息：

1. **崩溃 A 时，解码和载入全部成功**（"载入成功: 时长 250.11 秒"已经打印）。所以崩的不是解码，是**载入之后**的界面代码。
2. **崩溃 B 时还没有载入任何文件**（没有"载入请求"），视图刚挂载、用户一拖文件就崩。

两次都在 `GUIView` 的方法里、都在很浅的偏移、**栈里没有中间帧**。

## 二、反汇编定位到具体指令

用 `otool -tV -arch arm64` 反汇编已安装的二进制，算出偏移对应的那一条指令。
（崩溃帧记录的是**返回地址**，所以要看它前一条 `bl`：）

```
-[GUIView loadPath:] + 368   ← 紧跟  bl _objc_msgSend$setMaxValue:
-[GUIView hasAudioURL:] + 232 ← 紧跟  bl _objc_msgSend$containsObject:
```

两处都是「**给一个 ObjC 对象发消息**」。结合"浅偏移 + 无中间帧"，指向同一个结论：
**给一个已经被释放的对象发消息。**

## 三、根因：MRC 下把「自动释放对象」存进了裸指针

`gui.mm` 当时是手工内存管理（MRC）。问题出在两个地方：

### 1. 两个滑块 —— 既看不见，又会变成野指针

```objc
_st->offsetSlider = [NSSlider sliderWithValue:0 minValue:0 maxValue:1
                                  target:self action:@selector (offsetChanged:)];
_st->offsetSlider.frame = NSMakeRect (78, 126, 210, 22);
// ← 到此为止。没有 addSubview，也没有 retain
```

`sliderWithValue:...` 返回的是**自动释放对象**；存进 C++ 结构体的裸指针后
**没有任何人持有它**。事件循环排空 autorelease 池的那一刻它就销毁了。
之后 `loadPath:` 里执行 `_st->offsetSlider.maxValue = ...`
= 给已释放对象发消息 → **炸掉整个宿主**。

> 顺带一个用户可见的后果：这两个滑块**从来没被挂进视图**，
> 也就是说界面上根本看不到它们 —— 起始偏移滑块是核心功能。

### 2. 拖拽识别的静态集合

```objc
static NSSet* ok;
if (!ok)
    ok = [NSSet setWithArray:@[ @"mp3", @"wav", ... ]];   // ← 自动释放
```

`static` 变量一直持有这个指针，但对象本身是自动释放的。
首次拖拽时设置并在同一调用内使用（正常），
**池排空后 `ok` 就悬垂了**；AppKit 在同一次拖拽中会重复询问，
第二次走到 `[ok containsObject:ext]` → 炸。

## 四、修复

| # | 改动 | 说明 |
|---|---|---|
| 1 | 两个滑块 `addSubview` 进视图层级 | 同时修好"野指针"和"界面上看不见" |
| 2 | 静态集合改 `[[NSSet alloc] initWithArray:]` | 引用计数 +1、进程内永生，不再悬垂 |
| 3 | **`gui.mm` 全面改为 ARC** | 从根上消除这一整类 bug（编译器兜底） |
| 4 | `crashguard.mm` 升级为 `sigaction + SA_SIGINFO` | 日志新增故障地址 + 寄存器现场 |

第 3 项是**结构性修复**：这类"对象生命周期靠人脑记"的错误，
以后在 `gui.mm` 里根本写不出来。改动只有 4 处
（2 个 `[super dealloc]`、2 个 `[obj release]`）。

## 五、我做了什么来**证明**修好了

新建 `gui_repro.mm`：一个独立的 AppKit 程序，用**真实的 GUIView**，
按崩溃日志里的时序驱动它（建视图 → 排空 autorelease 池 → 触发动作）。

## 六、顺手堵掉的一个构建陷阱

新加的验证第一次跑出了"崩溃"，查下来是**假警报**：
`build.sh` 里编译测试程序用了 `| head -5`，clang 的警告写满 5 行后
head 退出并关闭管道，**clang 收到 SIGPIPE 被中途杀掉** ——
产物根本没生成，脚本却拿着**上一次的旧二进制**去跑验证。

已封装 `build_test()`：输出写进 `.log`、失败立即中止并打印错误，
并对 `validate` / `e2e_test` / `race_test` / `decode_probe` / `gui_repro`
五处全部生效。以后不会再有"假通过"。
